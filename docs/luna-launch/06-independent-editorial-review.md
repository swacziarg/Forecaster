# 06 — Independently audit the candidates

Read `docs/luna-launch/README.md`. Execute in a fresh Luna task that did not author tasks 01–05. This is an independent agent audit and a concrete packet for human editorial approval, not a fabricated human sign-off.

## Inputs and ownership

Read all completed candidate packets, the original research brief counterparts, `docs/adr/001-generalized-event-studies.md`, portfolio/Oscars editorial requirements, and the actual validators. Own `docs/launch-work/editorial-review/` and completion `06.md`. Do not modify candidate facts, source captures, scores, statuses, or runtime code during the audit.

## Execute

1. Check packet authorship and record your actual available task identity, role as an AI reviewer, review time, and file hashes. Never invent a person's name or claim blinded review: prior measurements already exist. If you authored a candidate, mark its independent review incomplete and still finish the other checks.
2. Review narrative selection, significance, distinct information clusters, neutral copy, mechanism, competing explanations, exact contract semantics, and source timing before consulting the calculated ranking where practical. Record any exposure to prior scores.
3. For every selected pre-reveal claim inspect the actual retained source passage and timing rationale. Check cited hashes against local bytes. A link, page date, or current snapshot alone does not prove historical availability. Call out nulls, mismatched identifiers, unverifiable public minutes, or source updates that break the cutoff.
4. Independently replay each potentially eligible five-card set through current application functions. Verify contract side, all windows, gaps/rejections, ties and comparable pairs, ending exclusion, frozen selection history, and anchor corrections.
5. Apply all topic-specific gates, including immutable final-whistle evidence, ABC transcript timing, TikTok disputes, repeated Butler content, Oscars rubric/coverage and redundant precursors, and reserve selection integrity.
6. Write one verdict per candidate: `ready-for-human-approval`, `changes-required`, or `blocked`, with claim-level reasons and exact remedial tasks. Record measurements separately from editorial rationale. Do not soften a failure because the queue is short.
7. Produce `approval-packet.md` and a structured `review.json` listing exact candidate/study versions, file hashes, proposed five cards and copy, caveats, your verdict, and clearly empty human approver/time fields. Recommend the release preference order without assigning dates. A human must be able to approve specific artifacts without reconstructing this conversation.

## Done when

Every available candidate has an auditable verdict; absent candidate work is explicitly missing. The approval packet is concrete. No runtime publication status or schedule changes, and no invented independence or human approval.
